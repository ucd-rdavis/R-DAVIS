CLAUDE.md

Guidance for working in the R-DAVIS repository: the source and published site for R for Data Analysis & Visualization in Science, a quarter-long graduate course at UC Davis. The site is served from GitHub Pages at https://ucd-rdavis.github.io/R-DAVIS/.

What this repo is

An R Markdown website (not a package, not a Quarto project). Every top-level .Rmd is one page; _site.yml defines the navbar and shared HTML output options; rmarkdown::render_site() renders everything into docs/, which GitHub Pages serves. The rendered docs/ directory is committed, so source edits are not live until the site is re-rendered and docs/ is committed too.

Course content is adapted from Data Carpentry’s R for Ecologists lesson, Software Carpentry’s gapminder-based R lesson, and prior UC Davis iterations. Data Carpentry material is CC-BY, so lessons that borrow from it end with an attribution line — keep those when editing and add one when borrowing more.

Layout

Path Purpose
_site.yml Navbar, output dir (docs), theme (flatly), toc/code-folding defaults, style.css, header.html. Add a page here or it won’t appear in the nav.
index.Rmd, outline.Rmd, syllabus.Rmd, contact.Rmd, resources.Rmd Course-level pages. outline.Rmd holds the weekly schedule with links to lessons, labs, and Canvas submission pages.
computer_setup.Rmd, setting_up_git.Rmd Pre-course setup pages.
lesson_wkNN_<topic>.Rmd One lecture page per week (week 6 is the midterm and has no lesson). Naming is lesson_wk + two-digit week + short topic.
labs.Rmd Lab index page: one ### <small>Lab Week N</small> {#lab-week-N} tab per week holding a one-sentence description and a download link. The outline links to these anchors.
labs/ The labs themselves, one lab_week_NN.qmd per week. render_site() does not render .qmd files; it copies them unchanged into docs/labs/, where students download them, fill them in, and render locally. Never put solution code in these files — the source is what students receive.
data/ Datasets. Served publicly by GitHub Pages at https://ucd-rdavis.github.io/R-DAVIS/data/<file>; lessons and labs read from those URLs so students never need local copies.
data_output/, figures/, results/ Example outputs that mirror the folder structure students are taught to create in their own projects.
img/ Images referenced by lessons.
docs/ Rendered site. Never hand-edit. Regenerated by render_site(); includes copies of data/, img/, etc.
archive/ Past-year lessons (2018–2020F prefixes, bonus_*) kept for reference and mined when reviving content. Also holds the retired Dates & Lubridate and Review & Markdown lessons and the Mauna Loa dates lab (2026 reorg). Not in the navbar.
scratch/ Instructors’ live-coding scripts used to record lecture videos; not rendered.
scripts/ One-off utilities (e.g., processing Garmin .fit files for exam data).
packages.txt, website_package_dependencies.R Rough dependency lists; neither is authoritative.
R-DAVIS-syllabus.md, CODE_OF_CONDUCT.md, license.md Plain-markdown metadata; the .md files are also rendered to docs/.

The core dataset

data/portal_data_joined.csv (Portal Project rodent surveys, ~35.5k rows, 13 columns: record_id, month, day, year, plot_id, species_id, sex, hindfoot_length, weight, genus, species, taxa, plot_type). Weeks 3–5, 7, and 10 and most labs use it, always via the GitHub Pages URL. surveys.csv, species.csv, plots.csv, and combined.csv are its unjoined components; tail_length.csv is a companion table used to teach joins; data_output/surveys_complete.csv is the NA-free version. Other datasets: gapminder.csv (labs and functions), mauna_loa_met_2001_minute.csv (iteration lab; 43 MB, read from the URL), mysteryData.csv (faceting challenge), and the nyc_13_* and tyler_activity_laps_*/finals_data.csv files, which are exam material.

Building

rmarkdown::render_site()                          # whole site -> docs/
rmarkdown::render_site("lesson_wk04_data_manipulation_pt1.Rmd")  # one page
rmarkdown::clean_site()                           # wipe docs/ first if things look stale

Or in RStudio: Build tab → Build Website. Rendering runs every code chunk, so the build needs a network connection (chunks read data from the live site URL) and every package any lesson loads. tidyverse covers most of it; week 8 (Data Visualization II) additionally needs viridis, cowplot, plotly, RColorBrewer, sonify, seewave, and BrailleR; week 9 (Functions) needs gapminder; computer_setup.Rmd needs emojifont.

Things to know before rendering:

  • Some setup chunks call install.packages() on missing packages during render. Expect that, or install ahead of time. BrailleR is no longer on CRAN; install it with remotes::install_github("ajrgodfrey/BrailleR") or the week 7 build fails.
  • Rendering outside RStudio needs pandoc on the path; the simplest option is export RSTUDIO_PANDOC=/Applications/quarto/bin/tools/<arch> (Quarto’s bundled copy).
  • Week 8’s sonification chunks (savewav, sonify) are eval=FALSE; the audio the page plays lives in img/*.wav. Re-enable them only to regenerate those files.
  • docs/ copies data/ wholesale, so the repository carries every dataset twice. Keep new datasets small (or read them from an external URL) and avoid committing anything that isn’t needed by a lesson.
  • render_site() renders every .md at the top level, including this file; the resulting docs/CLAUDE.html is gitignored, so ignore it or delete it after a build.
  • GitHub Pages is case-sensitive; macOS is not. Match file-name case exactly in img/ and data/ references.

Authoring conventions

  • Page skeleton: YAML title → a <div class = "blue"> block with ### Learning objectives → ## Videos (UC Davis Kaltura links plus a Canvas “Video Discussion” link) → ## In Class Coding (Canvas submit link) → content → attribution line.
  • Callouts: <div class = "blue"> … </div> for tips, challenges, and MCQs (.blue and .golden are defined in style.css). Every opening <div> must be closed, and leave a blank line after the opening tag; an unclosed div makes pandoc swallow the rest of the page into the callout.
  • Challenge answers: <details><summary>ANSWER</summary> wrapping an R chunk, so answers are collapsed by default but still execute at render time — they are verified by the build, so keep them runnable.
  • Chunk options: the purl= flags are inherited from Data Carpentry and are harmless. Use eval=FALSE for illustrative code (e.g., install.packages(), View(), absolute paths).
  • Data access in code: always https://ucd-rdavis.github.io/R-DAVIS/data/..., never a local path, so chunks run for students and for the site build alike.
  • Student-facing paths: students work in an RStudio project named R_DAVIS_<year> with data/, scripts/, figures/, and data_output/ subfolders; labs are the downloaded labs/lab_week_NN.qmd files, rendered to HTML and uploaded to Canvas. Keep instructions consistent with that layout.
  • Semester-specific links (Canvas assignment IDs, Kaltura video IDs, room and date info in index.Rmd/outline.Rmd, the project-name year) change every offering. When updating one, search all pages for the same ID.
  • Tone: conversational, second person, ecological examples, Talking Heads jokes welcome.

Working in this repo

  • Edit .Rmd sources, then re-render; don’t patch docs/ HTML directly.
  • Verify numeric claims in prose (row counts, “there are 25 species”, quartile cutoffs) against the actual data when touching a lesson — several were written for older versions of the dataset.
  • Do not push to GitHub or open PRs without explicit approval from the maintainer. Commits to main publish to the live course site once docs/ is included.
